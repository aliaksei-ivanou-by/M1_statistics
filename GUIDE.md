# Как вести отчеты 1-2-1

Инструкция по структуре репозитория, формату отчетов и скрипту сводки. Общая статистика по команде — в [README.md](README.md).

## Структура

```
M1_statistics/
├── README.md            # команда и статистика
├── GUIDE.md             # эта инструкция
├── AGENTS.md            # инструкции для AI-агента
├── CLAUDE.md            # ссылка на AGENTS.md для Claude
├── templates/
│   ├── month.md         # шаблон файла за месяц (шапка)
│   ├── report.md        # шаблон блока одной встречи
│   └── summary.md       # шаблон сводки за месяц
├── summaries/
│   └── 2026-10.md       # сводка по всем сотрудникам за месяц
├── scripts/
│   └── summary.ps1      # сбор оценок из отчетов (PowerShell)
└── employees/
    └── {Familiya_Imya}/
        ├── 2026-10.md
        └── ...
```

- **Папка сотрудника:** `employees/Familiya_Imya` латиницей, например `employees/Zakrevsky_Evgeny`.
- **Файл месяца:** `ГГГГ-ММ.md`, например `2026-10.md`, чтобы файлы сортировались по порядку.
- **Несколько встреч в месяце:** один файл. Шапка из `templates/month.md`, затем по блоку из `templates/report.md` на каждую встречу в хронологическом порядке.
- **Даты** внутри отчетов всегда в полном формате `ГГГГ.ММ.ДД`, например `2026.10.23`.

## Скрипт сводки

Запуск из корня репозитория в PowerShell:

```powershell
.\scripts\summary.ps1 -Month 2026-10    # таблица оценок за месяц для summaries\
.\scripts\summary.ps1 -Csv ratings.csv  # все встречи в CSV для графиков (открывается в Excel)
.\scripts\summary.ps1 -Check            # проверка, что блок yaml совпадает с отчетом
```

Скрипт читает блоки yaml под заголовком каждой встречи. Работает в Windows PowerShell 5.1 и PowerShell 7, дополнительные модули не нужны. Если запуск скриптов запрещен политикой, используйте `powershell -ExecutionPolicy Bypass -File .\scripts\summary.ps1 -Check`.

Файл скрипта сохранен в UTF-8 с BOM. Без BOM Windows PowerShell 5.1 неверно читает кириллицу, поэтому при редактировании кодировку нужно сохранять.

## Поля отчета

Поля и их порядок совпадают с формой ввода, поэтому значения можно переносить в форму по порядку. Кроме них в каждом блоке встречи есть служебные части, которых нет в форме: блок yaml с оценками и «Статус прошлых договорённостей».

| Поле | Что указываем | Формат |
|---|---|---|
| Мотивация | Насколько сотрудник заряжен и вовлечен | 1–5 (1 — низкая, 5 — высокая) |
| Выгорание | Признаки усталости и перегруза | 1–5 (1 — нет, 5 — сильное) |
| Удовлетворённость | Доволен ли работой и условиями | 1–5 (1 — низкая, 5 — высокая) |
| Категория блокера | Главный блокер | Одно значение: Процессы, Зарплата, Технологии, Команда, Переработки, Нет блокеров |
| Описание проблем | Что мешает работать эффективно | 2–3 предложения связным текстом, без списка |
| Договорённости (action points) | Что договорились сделать до следующей встречи | Обычный текст, один пункт на строку |
| Заметки менеджера | Дополнительные наблюдения | Свободный текст |
| Отношение сотрудника к double stuff | Как сотрудник относится к работе в двух командах | Свободный текст; «неприменимо», если сотрудник не на проекте |

## Правила заполнения

- Не выдумывать. Если информации нет, писать «нет данных».
- Оценка — только целое число 1–5, без пометок.
- Источники данных (PDP, заметки, транскрипты) в отчетах не упоминаются.
- Категория блокера — одна. Если блокеров несколько, выбирается главный, остальные упоминаются в «Описании проблем».
- Если по встрече нет договоренностей, в «Договорённостях» перечисляются темы, которые стоит поднять на следующей встрече.

Правила для AI-агента, который ведет отчеты, описаны в [AGENTS.md](AGENTS.md).
